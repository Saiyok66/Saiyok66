1. PROJECT OVERVIEW
================================================================

This is a browser-based web application that helps developers
and database administrators analyze and optimize SQL queries
in real-time. The tool provides:

  - Error detection (syntax mistakes, dangerous operations)
  - Performance suggestions (anti-pattern detection)
  - Plain-English query explanation
  - Optimized query output (rewritten SQL)
  - Quality score (0-100)

It uses a Node.js + Express backend with a custom SQL parsing
engine (no external AI API required), and a pure HTML/CSS/JS
frontend with a modern dark-themed UI.

4. HOW IT WORKS
================================================================

ARCHITECTURE FLOW:
  Browser (HTML/CSS/JS)
    |
    |--> POST /analyze   --> analyzer.js  --> JSON response
    |--> POST /optimize  --> optimizer.js --> JSON response
    |
  Express Server (server.js)

ANALYZE ENDPOINT (POST /analyze):
  Input:  { "query": "SELECT * FROM users;" }
  Output: {
    "success": true,
    "data": {
      "errors": ["Missing WHERE clause..."],
      "suggestions": [{ "type": "performance", "message": "...", "severity": "high" }],
      "explanation": "This query SELECTS ALL columns from USERS table.",
      "score": 65
    }
  }

OPTIMIZE ENDPOINT (POST /optimize):
  Input:  { "query": "SELECT * FROM users;" }
  Output: {
    "success": true,
    "data": {
      "original": "SELECT * FROM users;",
      "optimized": "SELECT col1, col2 FROM users LIMIT 1000;",
      "changes": ["Added LIMIT 1000", "Flagged SELECT *"],
      "improvementTips": ["Specify column names..."]
    }
  }

WHAT THE ANALYZER CHECKS:
  - Missing semicolons
  - Unmatched parentheses / quotes
  - SELECT without FROM
  - UPDATE/DELETE without WHERE (dangerous!)
  - Double commas, trailing commas
  - Empty WHERE clauses
  - SELECT * (performance issue)
  - Leading wildcards in LIKE
  - OR conditions (index prevention)
  - Nested subqueries
  - ORDER BY without LIMIT
  - Functions on columns in WHERE

WHAT THE OPTIMIZER DOES:
  - Flags SELECT * for replacement
  - Adds LIMIT 1000 to unbounded SELECTs
  - Converts != to <> (SQL standard)
  - Converts OR chains to IN()
  - Formats keywords to uppercase
  - Pretty-prints with line breaks
  - Suggests indexes for WHERE columns

7. VIVA / INTERVIEW EXPLANATION POINTS
================================================================

Q: What is this project?
A: It is an AI-powered web dashboard that analyzes and
   optimizes SQL queries. Users paste a query, and the tool
   finds errors, suggests improvements, explains the query
   in plain English, and outputs an optimized version.

Q: What technology did you use?
A: Frontend: Pure HTML5, CSS3, JavaScript (no frameworks)
   Backend: Node.js with Express.js
   No database required - it processes queries on the fly.

Q: How does the analysis work?
A: The analyzer uses pattern matching and regex-based rules
   to detect common SQL errors and anti-patterns. It checks
   for syntax issues (unmatched parentheses, quotes), dangerous
   operations (DELETE without WHERE), and performance problems
   (SELECT *, missing LIMIT, leading wildcards in LIKE).

Q: How does the optimization work?
A: The optimizer rewrites the query by:
   - Flagging SELECT * for explicit column selection
   - Adding LIMIT clauses to prevent full table scans
   - Converting OR chains to IN() for better index usage
   - Standardizing syntax (e.g., != to <>)
   - Formatting for readability (uppercase keywords)

Q: What is the quality score?
A: It starts at 100 and deducts points for each error (-15)
   and suggestion based on severity (high: -10, medium: -5,
   low: -2). It shows how well-written the query is.

Q: Why not use an AI API like OpenAI?
A: This project uses a custom rule-based engine, which means:
   - No API costs
   - No internet dependency
   - Faster response times
   - Full control over the logic
   It can be extended to use AI APIs if needed.

Q: How is the frontend-backend communication done?
A: The frontend sends HTTP POST requests using the Fetch API.
   The backend (Express) receives JSON, processes it through
   the analyzer/optimizer engines, and returns JSON responses.

Q: Is this project scalable?
A: Yes. The architecture separates concerns cleanly:
   - Frontend is static (can be CDN-hosted)
   - Backend is stateless (can be horizontally scaled)
   - New rules can be added to analyzer/optimizer easily

Q: What did you learn from this project?
A: RESTful API design, DOM manipulation, CSS layout/animation,
   regex-based text processing, Express middleware, deployment
   to cloud platforms, and full-stack development workflow.
